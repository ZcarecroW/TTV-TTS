TTV-TTS — Twitch chat read aloud by your own AI voices

An invisible OBS browser source that reads your Twitch chat in the viewer's language, with natural voices from Voice Creator Pro running locally on your GPU. No cloud, no subscription, no login.

Quick start Two-PC setup Create voices All options Troubleshooting

Overview

TTV-TTS is a single HTML file you add to OBS as a browser source. It listens to your Twitch chat, cleans up every message, detects its language, picks a voice and lets Voice Creator Pro (VCP) speak it. The audio plays inside the browser source, so it goes through the OBS mixer into your stream and recording.

Features

  • Anonymous chat connection – no Twitch login, token or bot account needed.
  • Language detection per message – English, German, Russian, Ukrainian, French, Spanish, Italian, Portuguese, Dutch, Polish, Turkish, Japanese, Chinese, Korean (and more scripts). Unclear short messages use the viewer's last language.
  • Voice per viewer – every viewer keeps a fixed “role” (e.g. young woman, elderly man) that is spoken by a native voice in each language.
  • Emotes – Twitch, BetterTTV, FrankerFaceZ and 7TV emotes are recognized; each emote is read once (“KEKW KEKW KEKW” → “kek”) or removed.
  • Emojis – common emojis become words (“😂” → “laughing”) instead of being spelled out.
  • Smart text cleanup – links, @mentions, letter spam (“sooooo”), ALL CAPS, abbreviations (“gg”, “brb”), blocked words, cheermotes.
  • Name announcements – “Max says: …” only when the speaker changes.
  • Low latency – first sound after ~0.7–0.9 s; the next message is generated while the current one plays.
  • Moderation – mod commands (!skip, !ttsclear, !ttsmute …); timeouts, bans and deleted messages are removed from the queue automatically.
  • Robust – auto-reconnect, warm-up after VCP restarts, self-healing for new voices, clear error messages in debug mode.

How it works

  1. The page joins your chat anonymously and loads the emote lists of your channel.
  2. For every message: filters (bots, commands, muted users) → split into words, emotes, emojis, links, mentions → language detection → cleanup → optional name announcement.
  3. The page asks VCP to speak the text (POST /api/v1/speak) with the chosen voice and language. VCP starts generating immediately and returns a stream ID.
  4. The page reads the WAV stream and plays it through Web Audio while VCP is still generating. The audio goes into the OBS mixer.
  5. As soon as VCP has finished generating the current message, the next one is already requested (prefetch) – so there is hardly any gap between messages.

Requirements

  • Voice Creator Pro desktop app (Windows or macOS) with its HTTP API enabled. A dedicated GPU with ~8 GB VRAM is recommended (tested on an RTX 3070 8 GB).
  • OBS Studio with the built-in browser source (OBS 30+ recommended; tested with OBS 32).
  • A streaming model in VCP for /api/v1/speak – Qwen3-TTS recommended (also streaming-capable: VoxCPM, Gepard).
  • Internet access on the OBS PC (Twitch chat and emote lists). VCP itself runs offline.
  • Optional: a second PC for VCP so the TTS load doesn't touch your gaming PC.

Quick start

A · Everything on one PC

  1. Install and start Voice Creator Pro, download the Qwen3 model, and enable the HTTP API in its settings (default port 8100). Optionally set an API key. → details
  2. Create voices: open voice-lab.html, pick your languages and press Start (or set a default agent voice in VCP and use voices.mode: 'single'). → details
  3. Open ttv-tts.html in a text editor and set at least: 
    twitch: { channel: 'your_channel_name' },
vcp: { baseUrl: 'http://127.0.0.1:8100', apiKey: 'YOUR_KEY_OR_EMPTY', … },
language: { default: 'en', … },
  4. Open connection-check.html, enter URL, key and channel, press Run all checks and try the speech test.
  5. In OBS add a Browser source → tick Local file → choose ttv-tts.html → tick Control audio via OBS → untick Shutdown source when not visible. → details
  6. Write something in your chat. Done.

B · VCP on a second PC

  1. Do step 1 above on the VCP PC.
  2. If you use Malwarebytes Windows Firewall Control on the VCP PC: add the authorized group VCP first (Security tab). → details
  3. On the VCP PC, right-click vcp-lan-setup.ps1 → Run with PowerShell and confirm the admin prompt. It prints the baseUrl to use. → details
  4. On the OBS PC continue with steps 2–6 above, using baseUrl: 'http://<IP of the VCP PC>:8101'.

Voice Creator Pro setup

Voice Creator Pro is a local text-to-speech, voice-cloning and voice-design studio. It runs entirely on your machine and ships a full REST API (docs: voicecreator.pro/api-docs).

1 · Install & models

  • Get the desktop app (Windows: Microsoft Store or itch.io · macOS: Mac App Store) from voicecreator.pro.
  • On first start the app installs its backend and downloads models. For TTV-TTS you need Qwen3-TTS: it supports streaming, voice design, cloning and 10 languages (English, German, Russian, French, Spanish, Italian, Portuguese, Japanese, Chinese, Korean). OmniVoice covers far more languages but does not stream.

2 · Enable the HTTP API

  • In the VCP settings, enable the HTTP API. The default port is 8100; you can change it in the settings or start the app with --api-port <port>. A port change needs an app restart.
  • The API listens on 127.0.0.1 only (this PC). For access from another PC see Network.
  • Test: open http://127.0.0.1:8100/api/v1/health in a browser on the VCP PC – it should show {"status":"ok"}.

3 · API key (recommended in a LAN)

Without a key anyone who can reach the port can use the API. Set a key in the VCP settings (or start with --api-key <key>). VCP accepts it as X-API-Key header, Authorization: Bearer header or ?api_key= URL parameter. TTV-TTS uses the URL parameter because it also works for audio streams. /api/v1/health and /api/v1/system/version never need a key.

4 · Default agent voice & model

VCP has a “default agent voice” and “default agent model” (MCP / agent voice settings). /api/v1/speak uses them when no voice/model is given. TTV-TTS uses them for the warm-up and as fallback when no voice pool exists. Set one – it avoids HTTP 400 No voice resolved.

5 · Quality tier

Qwen3 tierVRAMFirst audio*Generation speed*
Faster (0.6B)~1.7 GB~0.7–0.8 s~0.40 × real time
Higher quality (1.7B)~3.9 GB~0.7–0.9 s~0.47 × real time

* measured on an RTX 3070 8 GB with “low VRAM” mode on, model warm. Both tiers are more than twice as fast as real time, so 1.7B is the better choice on an 8 GB card. Switching the tier unloads the model and clears VCP's voice cache once.

6 · Warm-up after a VCP restart

The very first generation after VCP starts takes ~20–30 s (the model is loaded into the GPU). TTV-TTS sends a silent warm-up request as soon as it connects (vcp.warmup), so your first viewer doesn't wait. Best practice: start VCP before OBS and leave it running.

Voices

Saved voices vs. built-in speakers

  • Saved voices (clones and designed voices in your VCP library) are used via /api/v1/speak – streaming, lowest latency. This is the default (vcp.endpoint: 'speak').
  • Built-in speakers of Qwen3 (Vivian, Serena, Uncle_Fu, Eric, Ryan, Aiden, Ono_Anna, Sohee) are used via /api/v1/tts/generate with vcp.endpoint: 'tts' – no streaming, the whole message is generated first.

Naming convention for perUserLanguage

Voices are grouped into language pools by their name prefix voices.languagePrefix (default TTS-{lang} ). Inside a pool they are sorted by name, so the number defines the role:

#RoleEnglishGermanRussian…
1young womanTTS-en 1 EmmaTTS-de 1 LenaTTS-ru 1 Anya
2young manTTS-en 2 JakeTTS-de 2 JonasTTS-ru 2 Dima
3woman ~40TTS-en 3 RachelTTS-de 3 SabineTTS-ru 3 Olga
4man ~40TTS-en 4 MichaelTTS-de 4 ThomasTTS-ru 4 Igor
5elderly womanTTS-en 5 MargaretTTS-de 5 HelgaTTS-ru 5 Galina
6elderly manTTS-en 6 ArthurTTS-de 6 KlausTTS-ru 6 Viktor
  • A viewer is mapped to a role by a stable hash of their Twitch user ID. Keep all pools the same size – then the same viewer gets the same role in every language.
  • Languages without their own pool (e.g. French when you only created en/de/ru) use voices.fallbackPoolLanguage (default en) but are still spoken in their own language.
  • Changing the number of voices in a pool re-shuffles the roles of your viewers once.
  • Voices without the prefix (your other VCP voices) are ignored in this mode.

Creating voices with the Voice Lab

voice-lab.html automates the whole process for any of the 10 Qwen3 languages:

  1. Design – VCP creates each voice from an English description (“A woman around forty with a warm, calm and confident voice…”) plus a native-accent hint, speaking a neutral 6–8 s reference sentence in the target language.
  2. Check – VCP's speech recognition transcribes the sample; it must match the sentence (default ≤ 12 % word errors), be recognized as the right language and be 3–10 s long. Failed takes are redesigned automatically.
  3. Save – the sample becomes a saved voice named after the template (TTS-{lang} {n} {name}).
  4. Prime – one normal clone generation (see quirk below).
  5. Verify – a short /speak stream test.

Use Dry run first to listen to the samples without saving anything. Existing names are skipped, nothing is ever deleted. Timing on an RTX 3070: ~3 s per design, ~5 s per check, ~20 s per priming.

Creating voices by handYou can also design or clone voices in the VCP app and simply name them following the convention. A good reference clip is 3–10 s of clean speech with an exact transcript.

VCP quirk: “Generation failed” for brand-new voices

A voice that was saved through the API only streams via /api/v1/speak after it has been cloned normally once (VCP builds its voice prompt cache then). Before that, the stream is empty and the session reports Generation failed. Please try again.

  • ttv-tts.html handles this automatically: it primes the voice once (POST /api/v1/generation/clone?sync=true) and retries – the first message with that voice takes ~20 s longer.
  • voice-lab.html primes every new voice right after saving.
  • connection-check.html has a “Prepare (prime) voice” button.
  • The cache survives VCP restarts.

Tips

  • Cloned voices can speak other languages, but they keep the accent of their reference clip – that's why perUserLanguage uses one native voice per language.
  • Voices created with another model (e.g. OmniVoice) also work with Qwen3 via /speak; VCP does not switch models for them.
  • Avoid cloning real people's voices for your stream unless you have their permission.

Network: one or two PCs

One PC

Use baseUrl: 'http://127.0.0.1:8100'. No firewall changes needed. VCP and OBS share the GPU – fine for most setups, but heavy games may notice it.

Two PCs (VCP on a second machine)

VCP's API only listens on 127.0.0.1, so other PCs can't reach port 8100 directly. The solution is a Windows port proxy on the VCP PC: it accepts connections on 0.0.0.0:8101 and forwards them to 127.0.0.1:8100. Three things must be in place:

PieceWhySurvives a reboot?
Port proxy 0.0.0.0:8101 → 127.0.0.1:8100Makes VCP reachable from the LANYes (stored in the registry)
“IP Helper” service (iphlpsvc) runningIt is the program that runs the port proxyOnly if its start type is Automatic
Inbound firewall rule for TCP 8101Otherwise Windows drops all connectionsYes – unless a firewall manager deletes it (see Firewall)

Automatic: vcp-lan-setup.ps1 (recommended)

Run it on the VCP PC: right-click → Run with PowerShell. It requests admin rights by itself, sets up all three pieces, registers a scheduled task “VCP LAN Access” that re-checks them at every startup and logon, and prints a status report with the baseUrl to use.

powershell -ExecutionPolicy Bypass -File .\vcp-lan-setup.ps1            # install / repair
powershell -ExecutionPolicy Bypass -File .\vcp-lan-setup.ps1 -Check     # status report only
powershell -ExecutionPolicy Bypass -File .\vcp-lan-setup.ps1 -Uninstall # remove everything
powershell -ExecutionPolicy Bypass -File .\vcp-lan-setup.ps1 -ListenPort 8201 -VcpPort 8200

Manual (what the script does)

In PowerShell as administrator on the VCP PC:

netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8101 connectaddress=127.0.0.1 connectport=8100
Set-Service iphlpsvc -StartupType Automatic; Start-Service iphlpsvc
New-NetFirewallRule -Name 'VCP-API-Proxy' -DisplayName 'Voice Creator Pro API Proxy' -Group 'VCP' -Direction Inbound -Protocol TCP -LocalPort 8101 -Action Allow -Profile Any
netsh interface portproxy show v4tov4
Pasting multi-line commandsSome terminals paste multiple lines in the wrong order or one by one, which breaks blocks like if { … } or here-strings (@' … '@) with strange parser errors. Prefer the .ps1 file, or paste single-line commands one at a time.

Testing the connection

  • On the VCP PC: http://127.0.0.1:8101/api/v1/health → {"status":"ok"} means the proxy works.
  • On the OBS PC: connection-check.html, or in PowerShell:
Test-NetConnection 192.168.1.50 -Port 8101

A timeout (no answer) almost always means a firewall on the VCP PC drops the packets. “Connection refused” means nothing listens on 8101 (proxy or IP Helper missing).

Tips

  • Fixed IP: give the VCP PC a DHCP reservation in your router, otherwise its address may change and the baseUrl breaks.
  • Excluded ports: Hyper-V, WSL or Docker can reserve port ranges at boot (netsh int ipv4 show excludedportrange protocol=tcp). If 8101 is inside one, use another port (the script warns you).
  • VCP listening on all interfaces? If Get-NetTCPConnection -LocalPort 8100 -State Listen shows 0.0.0.0, you don't need the proxy – just a firewall rule for 8100.
  • macOS VCP: the script is Windows-only. On a Mac a TCP forwarder like socat TCP-LISTEN:8101,fork,reuseaddr TCP:127.0.0.1:8100 (Homebrew) does the same job; allow it in the macOS firewall. (Not tested by the author.)
  • Never forward these ports in your router to the internet.

Firewall

Windows Defender Firewall

Inbound connections are blocked by default on all profiles. The rule VCP-API-Proxy (TCP 8101, profile Any) opens exactly the proxy port. Your network profile (Public/Private) doesn't matter with -Profile Any; for a home network “Private” is the sensible classification anyway:

Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias 'Ethernet' -NetworkCategory Private

Malwarebytes Windows Firewall Control (WFC)

WFC sits on top of the Windows firewall. With Security → Secure Rules → “Delete unauthorized rules” enabled, it deletes every firewall rule that is not in one of its authorized groups – including rules you create with PowerShell. Typical symptom: everything works for a while, then suddenly stops (e.g. the next morning), and re-creating the rule only helps for seconds.

  1. Open WFC → Security.
  2. In “Define here a new authorized group” type VCP and click +. VCP appears under “Authorized groups”.
  3. Run vcp-lan-setup.ps1 (it creates the rule in group VCP). The rule now survives.

Alternative: create the inbound rule (TCP, local port 8101, allow) inside WFC itself – rules made there automatically belong to an authorized group. Leave “Secure Rules” on; it is a useful protection.

How to find out who deletes or changes rules

Windows logs every firewall rule change. In PowerShell (admin) on the VCP PC:

Get-WinEvent -LogName 'Microsoft-Windows-Windows Firewall With Advanced Security/Firewall' -MaxEvents 3000 |
  Where-Object { $_.Message -match 'Voice Creator|VCP-API-Proxy' } | Select-Object -First 5 |
  ForEach-Object { "==== {0}  ID {1}" -f $_.TimeCreated, $_.Id; $_.Message }

Event IDs (newer / older Windows builds): rule added 2097 / 2004 · rule modified 2099 / 2005 · rule deleted 2052 / 2006 · all rules deleted 2033. The full message names the modifying application and user. A rule that is “modified” right after it was added, or that disappears overnight, points to a firewall manager like WFC.

Other security suites

Norton, Kaspersky, ESET, Bitdefender, Avast, Comodo, GlassWire, simplewall, TinyWall, Portmaster and similar tools may use their own firewall or rule enforcement. Allow inbound TCP 8101 (or the program svchost.exe hosting the IP Helper service) in their settings. vcp-lan-setup.ps1 -Check lists third-party firewalls that are registered in Windows Security Center.

Chat features in detail

What is read

  • Normal messages, /me actions (“Bob dances”), replies (the leading @name becomes the name) and the text of sub/resub messages.
  • Not read: users in ignoreUsers, muted users, messages starting with !, cheermotes (Cheer100), and messages that end up empty after cleanup.
  • Timeouts, bans, /clear and deleted messages remove the affected messages from the queue – and stop them if they are playing.

Language detection

  1. Writing system: Cyrillic → Russian (Ukrainian if і/ї/є/ґ appear), Hangul → Korean, Kana → Japanese, Han → Chinese, plus Greek, Arabic, Hebrew, Thai, Devanagari.
  2. Latin script: counts typical words (en, de, fr, es, it, pt, nl, pl, tr) and special characters (ä ö ü ß, ñ ¿, ã õ, ą ł …).
  3. Unsure (e.g. “ok”, “gg”, a tie): the viewer's last detected language (for rememberUserMinutes), otherwise language.default.
  4. Emotes, emojis, links and mentions are ignored for detection.

Languages that VCP's model doesn't support are sent as Auto (Qwen3 has no Ukrainian, Dutch, Polish or Turkish – OmniVoice does).

Emotes

  • Twitch emotes come with position tags in every message; BTTV, FFZ and 7TV emote names (global + your channel) are loaded via their public APIs and refreshed every 10 minutes.
  • Only words that are emotes in your channel count as emotes. If your channel doesn't have e.g. KEKW as a 7TV/BTTV emote, “KEKW” is read as a normal word. Add it as an emote, or add a replacement: text.replacements.all: { 'KEKW': 'kek' }.

Emojis

With 'describe', known emojis become words in German, English or Russian (dictionary EMOJI_WORDS, easy to extend), each word once, max. 2 per message, separated by commas for natural pauses. Unknown emojis and emojis in other languages are removed.

Audio, latency & quality

Why Web Audio?

VCP streams a WAV file whose header declares a placeholder length (~2 GB) because the final length isn't known yet. Browser <audio> elements don't handle that reliably (cut-offs, silence). TTV-TTS therefore reads the stream itself and schedules the PCM data with Web Audio:

  • The audio engine runs at the stream's sample rate (24 kHz) – resampling happens once at the output, not per chunk.
  • Data is played in blocks of ≥ 0.5 s with tiny fades – no clicks at block borders.
  • The end of a message is detected when the last block has really finished playing (not by wall-clock time – OBS's audio clock may differ slightly).

playback: 'buffered' downloads the whole message first, fixes the WAV header and plays it with a normal audio element – the most conservative mode. Thanks to prefetch only the first message after a silence waits longer.

Typical latency

AI assistants (Claude, MCP)

VCP can be used directly by AI assistants – to speak notifications, read texts in your voices, transcribe audio, or to automate VCP through its REST API.

VCP's MCP server

VCP ships a Model Context Protocol server at http://127.0.0.1:8100/mcp (streamable HTTP). Tools:

ToolArgumentsWhat it does
vcp_speaktext, voice?, model?, language?, deliver? ('play'/'url')Speaks text in a saved voice – on the VCP PC's speakers (play) or as a stream URL.
vcp_list_voices–Lists saved voices (names and IDs).
vcp_transcribeaudio_base64, language?Speech-to-text with VCP's local ASR model.
MCP only works on the VCP PC itselfThe MCP endpoint has DNS-rebinding protection and only accepts requests addressed to 127.0.0.1/localhost. Through the LAN port proxy you get 421 Misdirected Request. Run the AI client on the VCP PC – or use the REST API from other PCs (it works through the proxy).

Claude Code

On the VCP PC (key as URL parameter, available in all your projects):

claude mcp add --transport http --scope user vcp "http://127.0.0.1:8100/mcp?api_key=YOUR_KEY"

Alternatively with a header (VCP accepts X-API-Key):

claude mcp add --transport http --scope user vcp http://127.0.0.1:8100/mcp --header "X-API-Key: YOUR_KEY"

Check with claude mcp list or /mcp inside a session; remove with claude mcp remove vcp. Then just ask, e.g. “Say ‘build finished’ in the voice TTS-en 4 Michael” or “List my VCP voices”.

Claude Desktop

Claude Desktop starts local MCP servers from claude_desktop_config.json (Windows: %APPDATA%\Claude\claude_desktop_config.json, macOS: ~/Library/Application Support/Claude/claude_desktop_config.json). The bridge mcp-remote (needs Node.js) connects it to VCP's HTTP endpoint:

{
  "mcpServers": {
    "vcp": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://127.0.0.1:8100/mcp?api_key=YOUR_KEY", "--allow-http"]
    }
  }
}

Restart Claude Desktop afterwards. Without an API key, drop the ?api_key=… part.

OpenAI-compatible endpoint

Tools that support OpenAI's text-to-speech API can use VCP as a drop-in: base URL http://127.0.0.1:8100/v1, endpoint POST /v1/audio/speech with input, voice (a saved VCP voice name) and response_format (mp3/wav); the key goes into Authorization: Bearer. Unknown OpenAI voice/model names fall back to VCP's default agent voice/model.

Let an AI build automations

The REST API is fully documented as OpenAPI: voicecreator.pro/api-docs (raw spec: https://voicecreator.pro/openapi-v2.json). Give that link to an AI coding assistant and describe what you want – the Voice Lab in this pack is exactly such an automation (design → transcribe → save → clone → speak). Useful hints for the AI: authenticate with ?api_key=, use ?sync=true for blocking calls, use /api/v1/speak with deliver: 'url' and read /api/v1/streaming/{id}/audio for low latency, and prime new voices once.

The helper tools

connection-check.html

Open it in Chrome/Edge/Firefox on the OBS PC. It checks: URL format → server reachable → API/CORS → VCP version → API key → model, quality & languages → default agent voice → voices & language pools → Twitch chat (anonymous join) → emote lists. Every failed step comes with a fix. The speech test plays a sentence in any voice/language and shows time to first audio, generation time, audio length and speed. voice-lab.html

Debug mode

Open ttv-tts.html in a normal browser with ?debug appended (e.g. file:///C:/TTS/ttv-tts.html?debug) or set debug: true. A panel shows chat status, VCP status and version, emote counts, voice pools and the queue, plus a live log of every message: detected language, voice, final text, warnings and errors. Type a test message with any user name and press Speak. Click into the page once – browsers only allow audio after a user interaction (OBS doesn't need that).

Performance

  • All AI work happens in VCP. In the browser source, processing one chat message takes ~0.013 ms and converting one second of audio ~0.08 ms; memory stays around 10 MB.
  • Without debug mode the page only logs warnings and errors (every console line is sent to OBS's main process).
  • Regex rules are compiled once, emote lists are re-validated with ETags, per-viewer data is pruned every 5 minutes.
  • The audio context keeps running while idle on purpose: restarting audio streams in OBS can make OBS increase its global audio buffering.
  • Biggest levers in OBS: 1 FPS for this invisible source; browser source hardware acceleration for visual overlays; a second PC for VCP if your game needs the whole GPU.

Security & privacy

  • Your configured ttv-tts.html contains your API key and IP. Don't share it or show it on stream.
  • Set an API key in VCP as soon as the API is reachable from the LAN. It protects all endpoints, including settings and app shutdown.
  • Never expose ports 8100/8101 to the internet (router port forwarding). There is no TLS.
  • The firewall rule uses profile “Any” for reliability. On a laptop that joins foreign networks, use -Profile Private and classify your home network as Private.
  • Twitch access is anonymous and read-only (justinfan login) – no token, the page can't write to your chat.
  • External requests: Twitch chat (WebSocket) and the public emote lists of BTTV, FFZ and 7TV. Nothing else, no tracking. Your chat text only goes to your own VCP.

FAQ

Does it cost anything per message?

No. VCP runs locally with unlimited generations; the emote and chat services are free.

Can I use it without a second PC?

Yes – one PC is the simplest setup. A second PC only helps if your game needs all of your GPU.

Can viewers choose their voice?

Not by command (yet). You can pin voices per viewer in voices.users.

Only read channel-point redemptions?

Create a reward that requires text, enable debug mode, redeem it once and copy the reward ID from the log into reading.rewardId.

Can it run on macOS / Linux?

ttv-tts.html runs in any OBS browser source. VCP exists for Windows and macOS. The LAN script is Windows-only (see the macOS note in Network).

Can I use another TTS engine?

The page talks to VCP's API. Other engines would need an adapter that offers the same endpoints.
